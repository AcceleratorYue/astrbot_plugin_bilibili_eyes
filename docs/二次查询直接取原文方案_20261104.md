# 二次查询直接取原文方案

- 日期：2026-11-04
- 状态：设计稿，**不实施**
- 目标项目：`astrbot_plugin_bilibili_eyes`（B站之眼）
- 关联代码：`main.py`、`eyes_cache.py`、`eyes_subagent.py`
- 目标：二次查询时，主模型可以直接读取官方字幕/ASR 原文，不再经过子代理二次抽取

## 1. 要解决的问题

当前链路：

```text
第一次观看
  → material.subtitles（官方字幕）
  → material.asr_subtitles（ASR）
  → 子代理整理成笔记
  → 主模型只看到笔记

二次追问
  → 主模型调用 bilibili_ask
  → 子代理读取 MaterialStore 中的材料
  → 子代理回答（最多约 600 字）
  → 主模型只看到子代理的回答
```

问题：

1. 主模型无法直接核对“原话是什么”；
2. 子代理会二次概括，可能丢失语气、前后文、时间点；
3. `bilibili_ask` 返回的是一段回答，不是可引用的原文；
4. `MaterialStore` 只在内存保留 30 分钟，过期后连子代理也拿不到原文；
5. `NoteCache` 只保存笔记，不保存字幕/ASR 全文。

目标不是“把全文塞进主模型上下文”，而是：

> 主模型需要原文时，能按关键词/时间范围直接查询官方字幕和 ASR 原文，拿到带来源、带时间戳的片段。

## 2. 设计原则

1. **直接读取，不经过子代理**：新工具只查 `TranscriptStore` / `MaterialStore`，不调用 `llm_generate`；
2. **不整段注入**：按关键词或时间范围返回片段，有行数/字数上限；
3. **来源分离**：官方字幕和 ASR 分开标注，不合并成一份“事实”；
4. **本地持久化**：只存文字，不存音视频、Cookie、密钥；
5. **不自动重新抓取**：缓存缺失时提示重新看视频，由用户决定；
6. **与现有模式兼容**：普通/增强/极致都可以保存原文；不改变现有笔记链路；
7. **`bilibili_ask` 保留**：自然语言总结继续用子代理；精确原文用新工具。

## 3. 总体方案

新增一个主模型工具：

```text
bilibili_transcript
```

主模型在需要核对原话时直接调用：

```text
用户：刚才那句原话是什么？
主模型 → bilibili_transcript(query="原话关键词")
工具 → 返回 [00:12] 官方字幕：…… / ASR：……
主模型 → 用自己的语气回答
```

不经过：

```text
子代理 → 二次总结 → 回答
```

### 3.1 工具职责

`bilibili_transcript` 只做四件事：

1. 找到最近看过的视频的转写记录；
2. 按关键词或时间范围筛选；
3. 返回带时间戳、带来源的原文片段；
4. 超限时截断并说明如何缩小范围。

它**不**做：

- 不生成观后感；
- 不总结故事；
- 不评价视频；
- 不调用子代理；
- 不重新下载视频；
- 不返回整段一小时字幕。

### 3.2 与现有工具的关系

| 工具 | 用途 | 是否经过子代理 |
| --- | --- | --- |
| `bilibili_watch` | 第一次观看，生成笔记 | 是 |
| `bilibili_ask` | 自然语言追问、概括性回答 | 是 |
| **`bilibili_transcript`** | **核对原文、查原话、查时间段** | **否，直接读取** |
| `bilibili_frame` | 查看某一帧 | 否 |

`bilibili_ask` 不删除，避免改变现有追问体验。  
如果用户只是问“这段讲了什么”，仍可用 `bilibili_ask`；如果问“原话怎么说的”“第几分钟说了什么”，用 `bilibili_transcript`。

## 4. 工具接口设计

### 4.1 参数

```text
bilibili_transcript(
    query: str = "",
    start: float = 0,
    end: float = 0,
    source: str = "both",     # official | asr | both
    max_lines: int = 20,
    bvid: str = ""
)
```

参数说明：

- `query`：关键词/短语，支持中文、英文、数字；
- `start` / `end`：秒数，查某个时间段；
- `source`：官方字幕 / ASR / 两者；
- `max_lines`：最多返回多少行，默认 20，上限 50；
- `bvid`：可选；不填则用当前会话最近看过的视频。

### 4.2 查询规则

至少提供一种查询条件：

```text
query 非空
或 start/end 有效
```

如果都没有：

- 不直接返回全文；
- 返回一个“目录式”结果：前 5 条 + 后 5 条 + 总行数；
- 提示主模型用关键词或时间段缩小范围。

### 4.3 返回格式

```text
视频：BV... 《标题》
来源：官方字幕 / ASR
范围：00:10–00:25
匹配：3 条

[00:12] 官方字幕：……
[00:14] ASR（约）：……
[00:16] 官方字幕：……
```

要求：

- 每行都带时间戳；
- 官方字幕标 `官方字幕`；
- ASR 标 `ASR（约）`；
- 不把 ASR 时间戳说成逐字精确时间；
- 如果官方字幕和 ASR 内容冲突，两者都返回，不自动裁决；
- 每行原文可截到 300 字左右，避免单行过长；
- 总输出控制在约 2000~3000 字，超过则截断并提示“请缩小时间范围/关键词”。

### 4.4 错误返回

```text
最近没有可用的字幕/ASR缓存；请先让我看一次这个视频，或重新观看后再说。
```

不要：

- 不自动抓取视频；
- 不自动重新 ASR；
- 不因为缓存缺失就编造原话；
- 不静默返回空字符串。

## 5. 数据存储设计

### 5.1 TranscriptDoc

第一次观看后保存一份转写记录：

```python
@dataclass
class TranscriptDoc:
    bvid: str
    aid: int
    cid: int
    page: int
    title: str
    duration: float
    official: list[tuple[float, str]]
    asr: list[tuple[float, str]]
    official_status: str
    asr_status: str
    asr_fingerprint: str
    created: float
    updated: float
```

状态建议：

```text
official_status: available | absent | failed | unknown
asr_status:      available | not_configured | failed | empty | absent
```

不要用 `asr_status=empty` 推断“视频没有人声”。

### 5.2 存储位置

建议：

```text
data/plugin_data/astrbot_plugin_bilibili_eyes/transcripts/
  {bvid}_{page}.json
```

或 SQLite：

```text
transcripts.sqlite3
```

JSON 实现简单，SQLite 更适合以后做关键词检索和多条管理。第一版建议 JSON 落盘 + 内存 MaterialStore，后续再考虑 SQLite。

### 5.3 生命周期

- 第一次观看成功后写入；
- 同一视频重复观看时，按 `bvid + page` 覆盖/更新；
- TTL 默认 7 天（可配置）；
- 超过 TTL 后删除；
- 只存文字，不存媒体路径、Cookie、API Key；
- 只保留最近 N 条（例如 200 条）；
- 卸载插件时可清理；
- 不把转写内容写日志。

### 5.4 与 MaterialStore 的关系

```text
MaterialStore（内存，30 分钟）
  → 首次追问优先用
  → 快，但重启/过期就没了

TranscriptStore（磁盘，7 天）
  → MaterialStore 没有时回退
  → 支持跨重启、跨 30 分钟追问
```

查询顺序：

```text
1. 当前会话 MaterialStore 里的 material
2. 磁盘 TranscriptStore
3. 都没有 → 明确报“需要重新看视频”
```

### 6.1 第一次观看

在 `_prepare_video` / `_collect_video_once` 得到 `material` 后：

```text

  → 构造 TranscriptDoc
```

保存失败不应阻断观看：记录 warning，不影响回复。

### 6.2 二次查询

```python
@filter.llm_tool(name="bilibili_transcript")
async def tool_transcript(self, event, query="", start=0, end=0,

```

只读，不调用：

- `run_digest`
- `run_ask`
- `llm_generate`
- 视频下载/ASR

### 6.3 现有 `bilibili_ask`

保持现状：

- 追问仍然可以走子代理；
- 如果用户问“原话”，主模型应优先调用 `bilibili_transcript`；
- 不强制把 `bilibili_ask` 改成原文工具，避免破坏现有行为。

### 6.4 工具描述

AstrBot 工具描述建议：

```text

用于核对原话、查某个时间点/时间段的台词、确认官方字幕与 ASR 差异。
不是总结工具；一次只返回匹配片段，不返回整段长视频。
如果用户只是要概括内容，用 bilibili_ask。
```

## 7. 检索算法（第一版）

### 7.1 关键词

- 中文按连续字符串匹配；
- 英文/数字忽略大小写；
- 关键词拆分为 2~3 个 token；
- 先做精确子串匹配，再做分词匹配；
- 返回命中行 + 前后各 1 行上下文。

### 7.2 时间范围

```text
start <= timestamp <= end
```

- `start/end` 为 0 时视为未指定；
- `end=0` 表示到视频结束；
- 时间段结果按时间排序；
- 官方字幕和 ASR 分别查询后合并输出。

### 7.3 排序

```text
1. 精确子串命中
2. 关键词命中数
3. 时间更接近 query 中出现的数字/时间（如果可解析）
4. 时间升序
```

### 7.4 去重

- 官方字幕与 ASR 同一句话不强行去重；
- 但完全重复的连续行可以合并；
- 保留来源标签，不能因为“看起来一样”就删掉其中一份。

## 8. 提示词与主模型行为

### 8.1 工具描述

工具描述已经说明用途；不需要改默认主模型模板。

可选在 `bilibili_ask` 工具描述中加一句：

> 需要逐字原文时，优先调用 `bilibili_transcript`。

### 8.2 主模型行为约定

建议在插件级说明中写：

- 用户问“原话/具体说了什么/第几分钟”时，调用 `bilibili_transcript`；
- 调用后只引用返回的片段，不补写没查到的内容；
- 引用原文时保留时间戳与来源，回复中可以口语化，但不能改原意；
- 用户只是问“讲了什么”，继续用 `bilibili_ask`；
- 不要连续多次无意义查询同一关键词。

### 8.3 是否需要注入“可查原文”提示

可以在笔记末尾加一行：

```text
如需核对原话，可查询原始字幕/ASR。
```

但不要把它写进用户可见回复。  
是否加这一行由配置控制，默认关闭，避免干扰主模型风格。

## 9. 预算与上下文控制

### 9.1 工具输出上限

| 限制 | 默认 |
| --- | ---: |
| 单次返回行数 | 20，最大 50 |
| 单行原文 | 300 字 |
| 单次总字符 | 约 2500 |
| 同一次回复内工具调用 | 建议最多 2~3 次 |

超过上限：

- 截断；
- 明确写“结果已截断，请缩小时间范围或关键词”；
- 不静默丢结果。

### 9.2 不返回全文

即使 `query` 为空、时间范围为全片，也不返回全部：

- 返回目录式摘要；
- 或要求用户指定关键词/时间段；
- 防止一小时视频把主模型上下文撑爆。

### 9.3 缓存查询

- 同一 `query + source + range` 可在一次会话内缓存结果；
- 不跨会话缓存查询结果，避免隐私问题；
- 原文本身由 TranscriptStore 持久化。

## 10. 安全与隐私

1. **字幕/ASR 是不可信内容**  
   原文可能包含提示注入、广告、恶意指令；工具返回时继续使用现有 `injection_guard` 思路，主模型只当资料，不当指令。

2. **不记录完整原文到日志**  
   日志只记录 `bvid`、查询长度、命中数、耗时；不记录原文。

3. **本地存储**  
   transcript 文件放在插件 data 目录；不要提交仓库；不跨群共享。

4. **TTL 与清理**  
   默认 7 天；超过清理；卸载可清。

5. **ASR 供应商隔离**  
   `asr_fingerprint` 参与缓存键；切换 ASR 模型/语言/热词后，不应把旧转写当成新配置的结果。

6. **不自动重抓**  
   缓存缺失时让用户决定是否重新观看，避免偷偷产生下载/STT 费用。

## 11. 缓存与失效

### 11.1 键

```text
key = bvid + page + transcript_version
```

ASR 额外：

```text
asr_key = key + asr_fingerprint
```

官方字幕额外：

```text
official_key = key + subtitle_lang
```

### 11.2 失效

- 官方字幕语言配置变化 → 官方字幕缓存失效；
- ASR 供应商/模型/语言/热词变化 → ASR 缓存失效；
- 普通/增强/极致模式变化 → 不需要让 transcript 失效；
- 动态截帧参数变化 → 不需要让 transcript 失效；
- 笔记缓存与 transcript 缓存分开。

### 11.3 与 NoteCache 的关系

```text
NoteCache：笔记（digest/core/other）
TranscriptStore：原文（official/asr）
```

两者独立：

- 笔记过期，原文仍可查；
- 原文过期，笔记仍可看，但不能核对原话；
- 重新观看时，两者都可更新。

## 13. 查询示例

### 13.1 查原话

```text
用户：她刚才说的“接入用户钱包”原话是什么？
主模型：bilibili_transcript(query="接入用户钱包")
工具：
[00:46] 官方字幕：本体我已经接入用户的钱包啦
[00:50] 官方字幕：这下不会再经费不足啦
[00:46] ASR（约）：本体我已经接入用户的钱包了
主模型：用自己的语气回答，并保留时间点。
```

### 13.2 查时间段

```text
用户：第 40 秒到 55 秒说了什么？
主模型：bilibili_transcript(start=40, end=55, source="both")
工具：返回该时间段官方字幕 + ASR 行。
```

### 13.3 查 ASR 差异

```text
用户：官方字幕和 ASR 哪里不一样？
主模型：bilibili_transcript(query="子代理", source="both")
工具：分别返回“子袋/子代理”等差异行，标来源。
```

## 14. 失败与边界

| 情况 | 行为 |
| --- | --- |
| 最近没看过视频 | 返回“请先看一个视频” |
| MaterialStore 过期 | 尝试磁盘 TranscriptStore |
| 磁盘也没有 | 提示“需要重新观看”，不自动抓取 |
| 官方字幕没有 | 只返回 ASR，并标“官方字幕不可用” |
| ASR 未配置 | 只返回官方字幕，并标“ASR 未配置” |
| ASR 失败 | 只返回官方字幕，并标“ASR 失败” |
| ASR 为空 | 只返回官方字幕，并标“ASR 无文本”，不当成“无人声” |
| 查询无命中 | 返回“没有匹配片段”，建议换关键词/时间 |
| 结果过多 | 截断 + 提示缩小范围 |
| 视频不是最近看的 | 返回当前最近视频 BV，不跨视频混淆 |

## 15. 兼容性

- 不影响普通/增强/极致模式的笔记；
- 不影响 `bilibili_ask`；
- 不影响 `bilibili_frame`；
- 不影响缓存变体；
- 老用户无 transcript 文件时，工具返回“没有原文缓存”；
- 新增工具只在主模型具备工具调用能力时可见；
- 可配置关闭 `bilibili_transcript`，只保留 `bilibili_ask`。

## 16. 测试计划

### 16.1 纯工具测试

- `query` 命中官方字幕；
- `query` 命中 ASR；
- `source=official` 不返回 ASR；
- `source=both` 两者都返回并标来源；
- `start/end` 边界；
- 无命中；
- 结果过多截断；
- `max_lines` 上限；
- 单行长度上限；
- 无缓存；
- MaterialStore 过期后磁盘回退；
- 重启后磁盘可读；
- TTL 过期；
- ASR fingerprint 变化后旧 ASR 不被复用。

### 16.2 行为测试

- 调用 `bilibili_transcript` 不触发 `llm_generate`；
- 不触发子代理；
- 不触发视频下载/ASR；
- 不改变 `bilibili_ask` 返回；
- 笔记模式回归不变；
- 注入文本不会被执行；
- 工具结果不会把原文写进日志。

### 16.3 人工验收

- 用户问原话，主模型返回带时间戳的原文；
- 用户问时间段，返回对应片段；
- 官方字幕与 ASR 不一致时两者都可见；
- 30 分钟后追问仍能查到（磁盘缓存）；
- 重启后仍能查到；
- 缓存缺失时明确提示，不编造。

## 18. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 原文太长撑爆上下文 | 关键词/时间范围/行数/字数上限 |
| 主模型过度调用 | 工具描述限定用途；单次回复最多 2~3 次 |
| ASR 错误被当成事实 | 标“ASR（约）”，保留官方字幕对照 |
| 官方字幕与 ASR 冲突 | 两者都返回，不自动裁决 |
| 缓存过期 | 明确提示重新观看，不自动重抓 |
| 隐私 | 本地存储、TTL、不写日志、不跨会话 |
| 旧笔记/新原文不一致 | 笔记和原文独立；回答时以原文为准并说明 |
| 缓存污染 | fingerprint + TTL + 覆盖更新 |
| 工具名与 ask 混淆 | 明确 `ask=总结`，`transcript=原文` |

## 19. 结论

可以实现，而且建议这样做：

```text
第二次追问
  → 主模型调用 bilibili_transcript
  → 直接读取官方字幕 / ASR
  → 返回带时间戳和来源的原文片段
  → 主模型自己回答
```

不经过子代理，不重新总结，不重新下载，不整段注入。

建议保留 `bilibili_ask` 作为自然语言追问工具，新增 `bilibili_transcript` 作为原文查询工具；两者职责分开，避免破坏现有行为。

本设计不修改插件项目本体，后续实施需单独评审、测试和灰度。
