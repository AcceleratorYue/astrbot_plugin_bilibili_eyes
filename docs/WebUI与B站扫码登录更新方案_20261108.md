## 1. 参考插件审计

### 1.1 WebUI 信息架构

参考插件是一个单页设置中心，没有独立服务器，通过 AstrBot Plugin View + `register_web_api` 工作。

导航结构：

```text
概览
登录
配置
  ├─ 连接与登录
  ├─ 模型与实况
  ├─ ASR 语音识别
  ├─ 画面证据
  ├─ 交互与频控
  ├─ 缓存与原文
缓存
诊断
```

页面特征：

- 左侧固定导航栏，分组显示“管理”和“配置”；
- 顶部标题 + 描述 + 登录状态 pill + 刷新 + 保存按钮；
- 概览页用 3 列状态卡展示登录、ASR、FFmpeg、视觉模型、帧缓存、游戏模式；
- 最近观看用紧凑表格；
- 运行信息用键值列表，支持复制数据目录和配置路径；
- 设置页每个分组两列表单，布尔值使用 switch，敏感字段只显示“已配置”；
- 有未保存更改时出现底部 savebar，支持保存、放弃、Ctrl+S；
- 删除/清空操作使用自定义 modal，不使用会被 iframe 拦截的 `window.confirm()`；
- 顶部和操作结果使用 toast；
- 支持浅色/深色主题；
- 响应式断点约 1180px / 860px。

### 1.2 平面设计特征

参考插件的视觉语言接近轻量 SaaS 控制台：

| 项目 | 设计 |
| --- | --- |
| 主色 | 蓝色 `#3f7cff` |
| 辅色 | 紫色 `#8b5cf6` |
| 页面背景 | 冷灰蓝 `#f4f6fb`，带轻微径向光晕 |
| 卡片 | 白色，14px 圆角，细边框 + 柔和阴影 |
| 侧栏 | 244px，半透明白/深色，sticky，带品牌标识 |
| 正文 | 深蓝黑 `#172033`，辅助文字 `#69758a` |
| 状态 | 绿色成功、橙色警告、红色错误、蓝色品牌标签 |
| 排版 | 系统无衬线字体，标题 22px，卡片标题 15.5px，说明 12.5px |
| 图标 | 内联 SVG，不依赖外部图标库 |
| 深色 | 独立 token：深蓝黑背景 `#0c1017`、面板 `#141a24` |
| 动效 | 页面切换轻微 rise，toast 滑入；不追求重动画 |

### 1.3 登录方式

参考插件使用 **B站官方扫码登录**，不要求用户手动抓 Cookie：

```text
POST /login/qr
  → passport.bilibili.com/x/passport-login/web/qrcode/generate
  → 返回 url + qrcode_key
  → 可选 qrcode 库本地渲染 PNG
  → 页面展示二维码（data URL，不经过第三方）

GET /login/status?key=...
  → passport.bilibili.com/x/passport-login/web/qrcode/poll
  → 86101 等待扫码
  → 86090 已扫码待确认
  → 86038 二维码过期
  → 0 登录成功，提取 SESSDATA / bili_jct / DedeUserID / refresh_token
```

凭据保存与优先级：

```text
插件 data 目录/credentials.json（扫码）
  > 插件配置 sessdata
  > 游客模式
```

登录后：

- 读取 `x/web-interface/nav`，展示昵称、UID、等级、大会员、头像；
- 头像下载成 data URL，规避防盗链/CSP；
- 登录凭据热生效，无需重启 AstrBot；
- 退出登录只清扫码凭据，自动回退到配置里的手动 SESSDATA；
- 另有 `/bili登录`、`/bili注销`、`/bili状态` 指令，作为 WebUI 不可用时的兜底；
- 凭据文件是明文 JSON，界面明确提示建议用小号、勿分享。

### 1.4 参考插件的后端能力

Web API：

```text
/status
/settings
/settings/save
/settings/reset
/login/qr
/login/status
/login/account
/login/logout
/cache
/cache/cleanup
/videos
/diagnostics
```

特点：

- 配置字段由服务端 `spec` 统一描述，页面不直接读 `_conf_schema.json`；
- 保存时服务端使用同一份 spec 做白名单校验；
- 保存后热更新插件配置对象、媒体提取器、原文缓存 TTL；
- status 返回版本、数据目录、配置路径、登录、ASR、视觉模型、FFmpeg、缓存、配额、已注册 API；
- 缓存清理在有活跃任务时拒绝清理帧/临时音频，避免边看边删；
- 登录账号信息有 10 分钟缓存，支持强制刷新。

## 3. 目标

### 3.1 目标

1. 把 WebUI 升级为完整的插件设置中心；
2. 保持现有视频记录、笔记详情、原文检索、缓存、诊断能力；
3. 新增 B站扫码登录，扫码凭据优先于手动 SESSDATA；
4. 支持分组编辑配置、保存、恢复默认、热生效；
5. 采用参考插件的冷蓝 SaaS 视觉语言、深色模式、响应式布局；
6. 不让 WebUI 变成必须依赖外部前端构建的项目。

### 3.2 非目标

- 不引入 Vue/React 构建链；
- 不实现任意历史视频全文检索；
- 不把 B站账号密码交给插件；
- 不实现多账号切换；
- 不在本轮重写视频理解核心；
- 不自动上传凭据到任何第三方服务。

```text
概览
登录
视频记录
视频详情（从视频记录进入，不占一级导航）

  ├─ 提示词

  └─ 等待与反馈

```

导航分组：

```text
管理：概览 / 登录 / 视频记录 / 原文检索
配置：10 个配置分组
维护：缓存 / 诊断
```

### 4.1 概览页

状态卡建议 6 个：

1. 登录状态：游客 / 昵称，来源扫码或配置，SESSDATA 尾部掩码；
2. 当前模式：普通 / 增强 / 极致；
3. 视觉子代理：跟随全局 / 指定 Provider；
4. 文本证据：官方/AI/OCR/ASR 当前可用情况；
5. 缓存：笔记、原文、帧的条数与体积；
6. FFmpeg / OCR 引擎：可用性、版本。

下方：

- 最近观看表格：标题、BV、模式、帧数、时间、是否有 OCR；
- 运行信息：版本、数据目录、配置路径、接口数量、服务时间、复制按钮。

### 4.2 登录页

两栏布局：

```text
左：账号卡 + 登录收益/安全提示
右：二维码卡 + 状态 + 刷新 + 复制链接
```

账号卡：

- 头像、昵称、UID、等级、大会员；
- 凭据来源；
- 1080P 已解锁标签；
- 退出登录。

二维码卡：

- 216×216 二维码；
- 等待/已扫码/成功/过期状态；
- 180 秒倒计时；
- 刷新二维码；
- 文本链接复制兜底。

### 4.3 配置页

- 每个分组独立视图；
- 字段两列布局，窄屏单列；
- 布尔值 switch；
- 敏感字段只显示“已配置/未配置”，输入留空表示保持；
- 高级字段折叠；
- 分组级“恢复默认”；
- 有未保存修改时导航出现数字徽标、底部出现 savebar；
- `Ctrl+S` / `Cmd+S` 保存；
- 保存前服务端白名单校验；
- 保存后热更新配置，不重启 AstrBot。

### 4.4 缓存页

展示：

- 笔记、原文、帧、临时音频的体积和数量；
- 按类型清理；
- 有正在处理的视频任务时，禁止清理帧/临时音频；
- 清理前后展示释放空间。

### 4.5 诊断页

展示：

- 版本、Python、平台；
- 数据目录、配置路径、凭据文件路径；
- 已注册 Web API；
- FFmpeg 探测结果；
- BiliClient 登录/游客状态；
- 最近错误摘要（不输出敏感信息）；
- 复制路径/复制诊断 JSON。

## 6. B站账号登录方案

### 6.1 新增模块

建议新增：

```text
eyes_auth.py
```

包含：

```python
class CredentialManager:
    # data/plugin_data/<plugin>/credentials.json
    def get_sessdata() -> str
    def save(credentials: dict)
    def clear()
    def has_valid_credential() -> bool

class BiliQrLoginService:
    def request_qrcode(qr_dir: Path | None) -> QrCodeSession
    def poll_status(qrcode_key: str) -> PollResult
```

### 6.2 二维码流程

```text
GET  https://passport.bilibili.com/x/passport-login/web/qrcode/generate
GET  https://passport.bilibili.com/x/passport-login/web/qrcode/poll?qrcode_key=...
```

轮询状态码：

| code | 含义 | UI |
| --- | --- | --- |
| 0 | 登录成功 | 保存凭据、刷新账号 |
| 86101 | 等待扫码 | 二维码下方提示 |
| 86090 | 已扫码未确认 | 提示手机确认 |
| 86038 | 二维码过期 | 显示过期遮罩、允许刷新 |

成功响应兼容：

1. `crossDomain` 票据链接：跟随请求，从 `Set-Cookie` 提取；
2. 普通 URL：从 query 参数回退解析；
3. 提取字段：`SESSDATA`、`bili_jct`、`DedeUserID`、`refresh_token`；
4. 如果没有 SESSDATA，视为失败，不保存空凭据。

### 6.3 本地二维码

- 使用可选依赖 `qrcode` 在本地渲染 PNG；
- 二维码内容含 `qrcode_key`，**不发送到第三方二维码服务**；
- Web API 把 PNG 转成 `data:image/png;base64,...` 返回；
- 未安装 qrcode 时，前端只展示登录链接和复制按钮，不阻塞流程。

### 6.4 凭据保存

```text
<AstrBot data>/plugin_data/astrbot_plugin_bilibili_eyes/credentials.json
```

建议内容：

```json
{
  "sessdata": "...",
  "bili_jct": "...",
  "dedeuserid": "...",
  "refresh_token": "...",
  "updated_at": 1790000000
}
```

要求：

- 原子写入（临时文件 + replace）；
- 文件权限尽量收紧；
- 不写进插件仓库；
- 不在 API 中返回完整 SESSDATA；
- 日志中只记录“已保存”，不打印凭据。

### 6.5 优先级

```text
扫码凭据 credentials.json
  > 配置项 sessdata
  > 游客
```

- 退出登录只删除 `credentials.json`；
- 删除后自动回退到配置里的手动 SESSDATA；
- 扫码成功/退出后要清空 `_client` 缓存和账号缓存，下一次请求立即使用新凭据。

### 6.6 账号信息

登录后调用：

```text
https://api.bilibili.com/x/web-interface/nav
```

读取：

```text
uname / mid / level_info.current_level / vipStatus / money / face
```

头像处理：

- 后端下载头像；
- 转 base64 data URL；
- 前端不直接依赖 B站图片域名，规避防盗链和 CSP。

账号信息缓存 10 分钟，登录/退出时强制刷新。

### 6.7 指令兜底

WebUI 不可用时保留指令：

```text
/bili登录   管理员申请二维码，发送图片或链接，后台轮询
/bili注销   清除扫码凭据
/bili状态   显示扫码/配置/游客状态、画质、OCR/ASR 状态
```

WebUI 和指令共用同一个 `CredentialManager` 和 `BiliQrLoginService`。

### 6.8 安全说明

- 凭据是明文 JSON，UI 必须提示“建议使用小号、不要分享 data 目录”；
- 不保存 B站密码；
- 不把 SESSDATA 回传给前端；
- 二维码只在本机渲染；
- 退出登录只清扫码凭据，不动用户手动配置的 SESSDATA；
- 如果 AstrBot 部署在公网，WebUI 必须依赖管理员登录和插件页鉴权，不额外暴露匿名 API。

## 7. 后端 API 方案

保留现有接口，新增：

| 方法 | 路由 | 用途 |
| --- | --- | --- |
| GET | `/status` | 版本、登录、模式、视觉/ASR/OCR、FFmpeg、缓存 |
| GET | `/settings` | 分组字段 + 当前值 + 敏感字段状态 |
| POST | `/settings/save` | 白名单校验并保存 |
| POST | `/settings/reset` | 分组/字段恢复默认 |
| POST | `/login/qr` | 申请二维码 |
| GET | `/login/status?key=` | 轮询状态 |
| GET | `/login/account` | 账号信息，支持 `refresh=1` |
| POST | `/login/logout` | 清除扫码凭据 |
| GET | `/cache` | 缓存统计（替代 `/cache-summary` 别名） |
| POST | `/cache/cleanup` | 带活跃任务保护的类型清理 |
| GET | `/diagnostics` | 诊断信息 |

兼容策略：

- 现有 `/overview`、`/videos`、`/video`、`/transcript`、`/cache-summary`、`/cache-cleanup` 保留；
- `/config` 保留为只读兼容别名，新页面使用 `/settings`；
- 路由仍以 `/astrbot_plugin_bilibili_eyes/...` 注册。

### 7.1 设置字段规格

建议新增：

```text
plugin_api/settings_spec.py
```

职责：

- 从现有 10 个配置分组生成字段；
- 为每个字段提供 label、类型、范围、选项、hint、advanced；
- 服务端用同一份 spec 做白名单校验；
- 页面不直接读 `_conf_schema.json`，避免配置页和 WebUI 漂移。

字段来源：

- 优先复用 `_conf_schema.json`；
- 对提示词等长文本使用 textarea；
- `sessdata` 改为 secret 类型，扫码登录成功后默认留空并显示“已配置”；
- `_grouped_config_migrated` 等内部字段不展示；
- 分组顺序复用 `CONFIG_GROUP_ORDER`。

### 7.2 保存逻辑

```text
POST /settings/save
  → 校验白名单/类型/范围
  → 写入分组配置
  → 调 AstrBot config.save_config_async（如果可用）
  → 更新插件内存配置
  → 清空缓存/客户端派生对象
  → 返回最新值 + 敏感字段状态
```

需要热更新：

- `sessdata` / 登录凭据 → 重建 `_client`；
- `cache_ttl_hours/max_entries` → 更新 NoteCache；
- `transcript_ttl_hours/max_entries` → 更新 TranscriptStore；
- `worker_threads/concurrency_limit` → 建议提示重启生效，或重建执行器；
- 其他行为配置下一次请求生效。

### 7.3 缓存清理保护

复用现有 `_active` 任务表：

```text
有正在处理的视频：
  - 可清理笔记/原文（按需）
  - 禁止清理 frames/cache 临时目录
  - 返回“任务进行中”
```

清理类型：

```text
notes / transcripts / frames / all
```

前端使用自定义 modal，不使用 `window.confirm`。

## 12. 风险

| 风险 | 应对 |
| --- | --- |
| B站二维码接口改版 | 兼容 crossDomain + query 解析；失败时提示手动 SESSDATA |
| 凭据明文保存 | 建议小号、权限收紧、UI 警告、退出清除 |
| qrcode 未安装 | 退化文本链接，不阻塞 |
| 配置字段过多 | 服务端 spec 分组/折叠/高级字段 |
| 保存破坏运行中任务 | 只热更新安全项；线程池相关提示重启 |
| 与 AstrBot 配置对象不兼容 | `save_config_async` / `save_config` / 文件回退三层 |
| iframe 限制 | 不用 `window.confirm`；使用页面 modal；`[hidden]` 规则 |
| 头像防盗链 | 后端转 data URL |
| 账号信息泄露 | API 只返回昵称/UID/等级/头像，不返回 Cookie |

## 13. 建议决策

1. **版本**：本次是 WebUI + 登录体系升级，建议 `0.13.1`；
2. **配置范围**：第一版展示全部安全配置，提示词等长文本折叠；
3. **登录入口**：WebUI 登录页为主，`/bili登录` 为兜底；
4. **凭据策略**：扫码凭据优先，退出后回退配置；
5. **视觉**：采用参考插件的冷蓝 SaaS 视觉，但保留 B站之眼品牌元素；
6. **实现顺序**：先后端认证/设置 API，再前端壳层和页面，避免先做静态 UI 后返工。
