# 极致模式设计方案（动态截帧 + 动态笔记预算）

- 日期：2026-11-04
- 状态：设计稿，**不实施**
- 目标项目：`astrbot_plugin_bilibili_eyes`（B站之眼）
- 参考调研：[调研报告_astrbot_plugin_video_storyboard_20261103.md](调研报告_astrbot_plugin_video_storyboard_20261103.md)
- 关联代码：`eyes_enhanced.py`、`eyes_subagent.py`、`main.py`、`eyes_cache.py`

## 1. 方案目标

新增第三个模式 **极致模式（extreme）**，不替代普通模式和增强模式。

三个模式并存，由用户按需求选择：

| 模式 | 定位 | 适合场景 |
| --- | --- | --- |
| 普通模式 | 固定 12 帧、轻量 | 日常快速看视频 |
| 增强模式 | 固定 24 帧、多张拼图 | 日常剧情/整活，比普通更完整 |
| **极致模式** | **动态帧数 + 动态笔记预算 + 可读性拼图** | 长视频、信息密度差异大、需要尽量不丢内容 |

极致模式要解决的问题：

1. 短视频不必截 12/24 帧；
2. 长视频不能只截 24 帧；
3. 有完整字幕/ASR 的对话/讲解可以少截；
4. 无字幕、ASR 无结果、快剪/哑剧需要多截；
5. 动态帧数带来的内容量变化，需要**动态笔记预算**，避免故事被固定字数截断；
6. 帧数增加后，还要受拼图可读性、图片数量、模型成本上限约束。

核心原则：

> 极致模式不是“帧数最多”，而是“在可接受成本内，让笔记覆盖足够多的故事节点”。

## 2. 三种模式的关系

### 2.1 现有模式不改变

- 普通模式：`frame_count=12`、固定笔记 2000 + 1000 字；
- 增强模式：`enhanced_frame_count=24`、固定笔记 4500 + 1500 字；
- 两者的采样、拼图、提示词、缓存行为保持现状。

极致模式是新增分支，不修改普通/增强的默认行为。

### 2.2 模式选择

建议新增：

```text
video_mode = normal | enhanced | extreme
```

兼容策略：

- 新配置 `video_mode` 存在时，以它为准；
- 没有 `video_mode` 时，旧 `enhanced_mode` 继续生效：
  - `false` → normal
  - `true` → enhanced
- `extreme` 只能显式选择，不会因为旧配置被误开启；
- 默认仍为普通模式（或保持用户当前设置），极致模式默认关闭。

这样可以避免一次升级把所有人的行为改掉。

## 3. 极致模式总体结构

```text
视频信息 / 字幕 / ASR
  → TextProfile（文本信息量）
  → 低分辨率画面扫描
  → VisualProfile（画面变化量）
  → 动态帧预算 FramePlan
  → 场景级分配 + 可读性多图规划
  → 候选帧抽取
  → 动态笔记预算 NoteBudget
  → 子代理生成核心内容 + 其他客观内容
  → 超预算时结构化压缩/分段生成（不盲目截断）
  → 主模型回复
```

与现有流程的区别：

| 环节 | 普通/增强 | 极致 |
| --- | --- | --- |
| 帧数 | 固定 | 动态 |
| 文本信息 | 主要用于笔记 | 参与帧预算 |
| 画面变化 | 选帧依据 | 参与帧预算 |
| 拼图 | 固定每张 6 帧 | 按可读性/像素预算自动 |
| 笔记预算 | 固定 | 按视频体量动态 |
| 超预算处理 | 截断 | 结构化压缩/分段生成 |

## 4. 输入信号

### 4.1 时长

```text
D = 视频秒数
D_min = min(D, 3600) / 60
```

时长只决定基础曲线，不直接线性乘帧数。

### 4.2 文本信息量

来源：

- 官方字幕 `material.subtitles`；
- ASR 补充 `material.asr_subtitles`；
- 文本状态：`official / asr / mixed / none / unavailable`。

不要用评论、弹幕、简介计算文本信息量。它们是观众内容，不是视频对白。

建议计算：

```text
coverage   = 文本覆盖的时间比例
density    = 每分钟有效字符数
diversity  = 不重复词/二元组比例
quality    = 官方字幕 1.0；ASR 0.75；混合 0.85；其他 0.5
text_info  = sqrt(coverage)
           * min(1, density / 240)
           * (0.55 + 0.45 * diversity)
           * quality
```

范围 0~1。

注意：

- 字幕只有起点时，用相邻行间隔估算覆盖；
- `always` 模式下官方字幕和 ASR 可能重复，取并集/较优来源，不要相加；
- 歌词、片头片尾、重复口播可能让密度虚高，需要去重和上限；
- ASR 失败/未配置不等于“视频没有人声”，只能说明文本证据不足。

### 4.3 画面变化量

极致模式复用 64×36 低分辨率扫描，得到：

```text
cut_rate    = 每分钟切镜数
mean_change = 平均变化分数
scene_count = 合并短镜头后的场景数
visual_info = 0.5 * min(1, cut_rate / 20)
            + 0.5 * min(1, mean_change / 0.4)
```

范围 0~1。

### 4.4 内容类型判断

不强制分类，只用于日志和解释：

```text
text_info >= 0.55                     → text-rich
visual_info >= 0.60 且 text_info < 0.30 → visual-fast
其他                                   → mixed
```

## 5. 动态帧预算

### 5.1 基础曲线

先用时长给“无文本、普通运动”的基础帧数：

| 视频时长 | 基础帧数 |
| --- | ---: |
| ≤15 秒 | 5 |
| 30 秒 | 7 |
| 60 秒 | 10 |
| 2 分钟 | 13 |
| 5 分钟 | 18 |
| 10 分钟 | 24 |
| 20 分钟 | 30 |
| 30 分钟 | 34 |
| ≥60 分钟 | 40 |

中间时长线性插值。

### 5.2 文本/画面修正

```text
text_factor   = 1 - 0.35 * text_info
visual_factor = 1 + 0.30 * visual_info

raw = base * text_factor * visual_factor
N = clamp(round(raw), floor(D), max_extreme_frames)
```

默认强度：

- 文本最多降低 35%；
- 画面最多提高 30%；
- 不做“有字幕就砍一半”，防止字幕质量差或字幕不是剧情主线。

最低帧数：

| 时长 | 最低帧数 |
| --- | ---: |
| ≤15 秒 | 4 |
| ≤60 秒 | 6 |
| ≤3 分钟 | 8 |
| ≤10 分钟 | 12 |
| >10 分钟 | 16 |

### 5.3 预算上限

```text
layout_cap = cells_per_sheet * max_extreme_sheets
N_actual = min(N, layout_cap)
```

如果 `N_actual < N`：

- 记录“图片数量/可读性上限将采样格数从 N 调整为 N_actual”；
- 笔记“不确定项/证据缺口”写清楚；
- 不把减少后的帧数说成完整覆盖。

### 5.4 极致模式的上限

| 参数 | 建议默认 |
| --- | ---: |
| 最大帧数 | 48 |
| 最大拼图张数 | 8 |
| 可读性目标 | `scene` |
| 每张像素预算 | 120 万 |

上限不是目标值；动态帧数超过上限时，先考虑增加图片数，仍不够再减少帧数并警告。

## 6. 场景级分配

### 6.1 划分区间

用切镜/变化密度：

1. 合并相邻短镜头；
2. 得到 5~12 个场景区间；
3. 每区间记录 `from/to/时长/画面变化/文本覆盖`。

### 6.2 权重

```text
weight_i = 0.25
         + 0.75 * visual_density_i
         + 0.25 * text_gap_i
```

- 画面变化越大，权重越高；
- 文本覆盖越低，权重越高；
- 文本密集区间权重下降，但不归零。

### 6.3 分配

1. 每区间先给 1 帧，保证覆盖；
2. 剩余帧按权重分配；
3. 单区间最多 3~4 帧；
4. N 小于场景数时合并短场景，不要丢掉中段；
5. 每区间取 25%/50%/75% 候选，优先非近黑、清晰、避开转场。

### 6.4 覆盖检查

- 任意超过 `2 * D / N` 的空白区间补 1 帧；
- 开头 5 秒、结尾 5 秒至少各 1 帧；
- 文本密集但时长长的区间也不能完全没有画面。

## 7. 可读性多图

参考 `astrbot_plugin_video_storyboard`：

1. 可读性目标：`shot` / `scene` / `text`；
2. 根据每张像素预算和格子尺寸，计算每张最多几格；
3. 根据最大图片数得到总容量；
4. 动态帧数不能超过总容量；
5. 每格记录：

```text
from / to / frame_at
readability
dark
page / 页码范围
```

B站之眼当前已有：

- 多张拼图（每张 6 帧）；
- 16:9 画布；
- DP 装箱；
- 核心/其他两份笔记。

极致模式需要补：

- 固定 6 帧 → 按可读性自动规划；
- 只有 `time` → 增加 `from/to/frame_at`；
- 增加 `readability/dark`；
- 把 `frame_plan` 摘要写进笔记和日志。

## 8. 动态笔记预算

这是极致模式区别于增强模式的第二个核心。

### 8.1 为什么不能固定

固定 4500 + 1500 字的问题是：

- 30 分钟视频 + 大量高信息评论，4500 字可能不够；
- 10 秒视频，4500 字又可能浪费；
- 动态帧数增加了画面证据，固定预算更容易截断故事。

所以极致模式使用：

```text
按视频体量估算 note budget
→ 在 prompt 里告诉子代理目标字数
→ 超预算时结构化压缩/分段生成
→ 不盲目按字符截断
```

### 8.2 估算输入

```text
D_min          = min(D, 3600) / 60
transcript_chars = 有效文本字符数（上限 12000）
frame_n        = 实际帧数
scene_n        = 场景数
comment_chars  = 评论原文总字符数（上限 20000）
comment_count  = 评论条数（上限 50）
danmaku_count  = 弹幕数量
```

### 8.3 核心/其他预算公式

```text
core_raw = 1500
         + 500 * sqrt(D_min)
         + 0.25 * min(transcript_chars, 12000)
         + 12 * frame_n
         + 40 * min(scene_n, 20)

other_raw = 800
          + 200 * sqrt(D_min)
          + 0.08 * min(comment_chars, 20000)
          + 3 * frame_n
          + 30 * min(comment_count, 50)

core_budget  = clamp(round(core_raw), 1500, 9000)
other_budget = clamp(round(other_raw), 800, 3500)

# 实际写给子代理的目标额度，留 10% 余量，减少“刚好超一点被截断”
core_prompt_budget  = round(core_budget * 1.1)
other_prompt_budget = round(other_budget * 1.1)
```

说明：

- `sqrt(D_min)` 让长视频增长，但不线性爆炸；
- `transcript_chars` 让文本信息多的视频有更多笔记空间；
- `frame_n` 让画面证据多的视频有更多空间；
- `comment_chars/comment_count` 给评论区留出预算；
- 上限防止单次输出过大，超出上限用结构化筛选。

### 8.4 示例

| 视频 | 核心预算 | 其他预算 | 总预算 |
| --- | ---: | ---: | ---: |
| 10 秒、少量文本 | 约 1900 | 约 900 | 2800 |
| 76 秒、普通评论 | 约 2700 | 约 1400 | 4100 |
| 5 分钟、字幕密集 | 约 4000 | 约 1800 | 5800 |
| 30 分钟、评论较多 | 约 7400 | 约 2700 | 10100 |
| 60 分钟、长字幕 | 约 9000（封顶） | 约 3500（封顶） | 12500 |

具体数值会随文本、帧数、评论数变化，表中只是量级示意。

### 8.5 防止截断

不能只把预算传给 `truncate_digest` 然后硬切。建议：

1. **软预算**：prompt 中写“目标 core X / other Y 字，优先保留故事与高信息内容”；
2. **结构优先级**：
   - 核心：故事梗概、连续叙事、关键对白、关键画面、不确定项；
   - 其他：客观信息、置顶/高赞/高信息评论、关键弹幕；
3. **超预算处理**：
   - 先压缩关键画面列表和重复解释；
   - 再压缩低信息评论/回复/@列表；
   - 不截断故事梗概和连续叙事；
4. **硬上限**：
   - core 9000、other 3500；
   - 硬上限只是防止模型上下文/输出失控的最后兜底，不是正常预算；
   - 超过硬上限时，优先分段生成：核心一次、其他一次，各自独立预算；
5. **明确标注**：
   - “评论区原文按信息量筛选，未全部列出”；
   - “长视频采样覆盖全片，但不等于每一帧都看过”。

### 8.6 可选：极致模式分两次子代理调用

当预估总预算超过阈值（例如 7000 字），或者单次输出仍超硬上限：

```text
第一次：核心内容（故事/叙事/对白/画面/不确定项）
第二次：其他客观内容（信息/评论/弹幕）
```

优点：

- 两次各自有预算，不会因为一个总输出上限互相挤占；
- 评论可以保留更多原文；
- 核心故事不会被评论区挤掉。

代价：

- 多一次模型调用，延迟和费用上升；
- 只应在极致模式使用，且可配置关闭。

## 9. 数据结构

```python
@dataclass
class TextProfile:
    status: str          # official / asr / mixed / none / unavailable
    coverage: float
    density: float
    diversity: float
    quality: float
    score: float
    warnings: list[str]

@dataclass
class VisualProfile:
    cut_rate: float
    mean_change: float
    scene_count: int
    score: float

@dataclass
class FramePlan:
    duration: int
    base: float
    text: TextProfile
    visual: VisualProfile
    target_frames: int
    actual_frames: int
    floor: int
    cap: int
    cells_per_sheet: int
    max_sheets: int
    reason: str
    warnings: list[str]

@dataclass
class NoteBudget:
    core_chars: int
    other_chars: int
    total_chars: int
    reason: str
    warnings: list[str]
```

每格布局：

```python
{
    "sheet": 1,
    "index": 1,
    "from": 12.0,
    "to": 18.5,
    "frame_at": 15.2,
    "readability": "scene",
    "dark": False,
    "tier": 3,
}
```

提示词明确：

- 每格只是 `frame_at` 的一帧，不是 `from~to` 的连续录像；
- `from~to` 是采样区间，不是精确镜头边界；
- 近黑/低可读性帧不能当成“该段没有内容”；
- 实际帧数可能少于目标帧数，缺口写进不确定项；
- 笔记不要超过预算，但优先保留故事和证据，不要为凑字数扩写。

## 10. 配置设计

### 10.1 模式

```text
video_mode = normal | enhanced | extreme
```

兼容旧配置：

```text
# video_mode 缺失时
enhanced_mode = false → normal
enhanced_mode = true  → enhanced
```

### 10.2 极致模式配置

```text
extreme_max_frames = 48
extreme_max_sheets = 8
extreme_readability = shot | scene | text
extreme_pixel_budget = 1200000

extreme_note_budget = dynamic | fixed
extreme_note_core_min = 1500
extreme_note_core_max = 9000
extreme_note_other_min = 800
extreme_note_other_max = 3500

extreme_split_notes = auto | always | never
```

默认：

- `extreme_note_budget=dynamic`；
- `extreme_split_notes=auto`；
- 普通/增强模式的 `digest_max_chars`、`enhanced_digest_max_chars` 不变。

### 10.3 旧字段处理

- `frame_count`、`enhanced_frame_count` 继续作为普通/增强的固定值；
- 极致模式不读取它们作为主参数，只在回退时使用；
- 旧 `enhanced_mode` 不删除，避免已有配置失效；
- 文档写清楚 `video_mode` 与 `enhanced_mode` 的优先级。

## 11. 数据流与代码结构

建议新增：

```text
eyes_extreme.py
  - TextProfile / VisualProfile / FramePlan / NoteBudget
  - estimate_text_profile()
  - estimate_visual_profile()
  - plan_frames()
  - estimate_note_budget()
  - allocate_scenes()
```

主流程：

```text
_collect()
  → _transcribe_audio_if_needed()
  → _fill_frames()
       normal    → _fill_frames_normal()
       enhanced  → _fill_frames_enhanced()
       extreme   → _fill_frames_extreme()
  → _digest()
       normal/enhanced → 固定预算
       extreme         → estimate_note_budget() + run_digest_extreme()
```

极致模式复用：

- `eyes_enhanced` 的低分辨率扫描、切点、候选帧；
- 现有 16:9 拼图/DP；
- 现有核心/其他输出标签；
- 现有缓存。

新增：

- 动态帧预算；
- 可读性多图规划；
- 动态笔记预算；
- 超预算结构化压缩/分段生成；
- `FrameLayout` 的区间/质量元数据。

## 12. 缓存影响

极致模式是新模式，不应破坏普通/增强缓存。

建议：

- 缓存 variant：
  - `normal_v6`（保持现有普通笔记缓存）
  - `enhanced_v6`（保持现有增强笔记缓存）
  - `extreme_v1`（新增极致笔记缓存）
- 不为了新增极致模式整体提升 `CACHE_VERSION`，避免普通/增强旧笔记无谓失效；
- 只有极致模式自己的 planner 版本/配置变化时，失效 `extreme_v1`；
- 极致模式的 key 增加：
  - `frame_plan_version`
  - `video_mode=extreme`
  - `extreme_*` 配置摘要
  - 文本状态（official/asr/none）
- 同一个视频切换到普通/增强/极致，应该生成不同笔记；
- 不把完整 `FramePlan` 塞进 key，只放版本和影响结果的配置摘要。

## 14. 验证方案

### 14.1 纯规划器测试

不跑视频、不调模型：

- 10s 无文本 → 帧数 ≤ 8；
- 60s 无文本 → 8~12；
- 5min 文本高 → 低于 5min 无文本；
- 30min 无文本 → 明显高于 24；
- 30min 文本高 → 低于 30min 无文本；
- 超过 `max_sheets * cells_per_sheet` → 截断并 warning；
- `text_info=0` 且 ASR 未配置 → 帧数提升，但不得输出“视频无人声”的结论；
- 任意配置都不会低于 floor 或高于 cap；
- 笔记预算随文本/帧数/评论增长，但不超硬上限。

### 14.2 三模式回归

- 普通模式：帧数、笔记预算、缓存、提示词与 0.9.0 一致；
- 增强模式：24 帧、4500 + 1500、缓存与 0.9.0 一致；
- 极致模式：只在新模式启用时生效；
- `video_mode` 缺失时，旧 `enhanced_mode` 迁移正确；
- 切模式不会串缓存。

### 14.3 离线 A/B

样本：

- 短视频（<60s）：无字幕/有字幕；
- 中视频：对话/讲解、vlog；
- 长视频：播客/教程、快剪/哑剧；
- 官方字幕、只有 ASR、完全无文本。

对比：

- 增强模式固定 24；
- 极致模式动态。

评价：

- 盲测：只看笔记能否讲清“谁、想做什么、发生什么、转折、结局”；
- 关键节点覆盖率；
- 是否出现“单帧当整段”；
- 帧数/图片数/耗时/费用；
- 笔记是否明显优于固定预算且没有截断。

### 14.4 灰度

- 极致模式默认关闭；
- 先 dry-run 日志；
- 再 opt-in；
- 再考虑推荐配置；
- 保留 `video_mode=enhanced` 作为稳定回退。

## 15. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 文本密度高但内容无关 | 去重、覆盖/多样性、最多降 35% |
| ASR 错误/空文本 | 质量权重；区分无音轨/未配置/失败/空文本 |
| 长视频被图片上限截断 | 记录 warning；允许更多图；极致模式上限 8 张 |
| 快剪切镜误检 | 延续切点抑制；候选帧避开转场 |
| 文本高但画面有重要信息 | 保留 floor，不归零画面 |
| 笔记预算过大导致模型超时 | 硬上限 + 分段生成 |
| 笔记预算过小导致截断 | 动态估算 + 结构化压缩 |
| 极致模式成本高 | 默认关闭；清晰标注；A/B |
| 三模式配置混乱 | `video_mode` 明确；旧 `enhanced_mode` 兼容；文档说明 |
| 缓存串模式 | variant 分开；旧模式缓存不动 |
| 动态行为难调试 | 日志输出 FramePlan / NoteBudget 原因 |

## 16. 分阶段落地建议（后续实施）

### Phase 0：设计冻结

- 评审本文档；
- 确认三模式命名、配置兼容、预算公式；
- 不写业务代码。

### Phase 1：纯规划器

- `eyes_extreme.py` 纯函数；
- 单元测试覆盖帧数、笔记预算、floor/cap；
- 不接入插件。

### Phase 2：极致模式取帧

- `video_mode=extreme` 分支；
- 复用低分辨率扫描；
- 动态帧数 + 可读性多图；
- 输出 dry-run 日志；
- 普通/增强完全不走该分支。

### Phase 3：极致模式笔记

- 动态 NoteBudget；
- 子代理 prompt 带预算；
- 超预算结构化压缩；
- 必要时分两次调用；
- 保留核心/其他标签。

### Phase 4：模式选择与 UI

- `video_mode` 配置；
- 旧 `enhanced_mode` 迁移；
- 文档、README、配置说明；
- 三模式对比表。

### Phase 5：A/B 与默认

- 对比普通/增强/极致；
- 确认没有破坏现有模式；
- 决定是否推荐极致模式，而不是强制默认。

## 17. 不做什么

- 不让极致模式替代普通/增强；
- 不因“有字幕”把画面砍到只剩 1 帧；
- 不按分钟线性加帧；
- 不把评论/弹幕当文本信息量；
- 不把 ASR 失败当成“视频无声音”；
- 不用更多小格子替代可读性；
- 不在没有 A/B 的情况下把极致模式设为默认；
- 不复制参考项目的 Apache-2.0 代码。

## 18. 结论

极致模式可以独立成立：

```text
普通模式：固定 12 帧 + 固定笔记，轻量
增强模式：固定 24 帧 + 固定笔记，日常完整
极致模式：动态帧数 + 动态拼图 + 动态笔记预算，长/复杂视频
```

它不会取代已有模式，而是给用户第三个选择：

- 短视频/日常：普通或增强；
- 长视频/信息密度差异大/不想被固定预算截断：极致；
- 极致模式默认关闭，用户显式选择。

本设计不修改 B站之眼项目本体；后续实施需单独评审、测试和灰度。
