# B站之眼「增强模式」落地方案（v0.7.0 已实施）

> 目标：**现有普通模式与全部钩子保持不变**，新增一个默认关闭的增强模式。  
> 增强模式复用 SeeNow 的「变化选帧 + 档位 + 完整 DP 拼图装箱」方案，并放宽笔记内容阈值。  
> 本方案已按确认参数实施：`enhanced_mode`、16:9 矩形 DP、默认 24 帧、笔记上限 4500。
> 最终行为以 README / 代码为准；下文保留设计过程。

---

## 1. 硬约束

1. **普通模式行为不变**
   - `frame_source` 的 `hotspot` / `uniform` 逻辑不动；
   - `subagent_frame_mode` 的 `individual` / `contact_sheet_plus` 逻辑不动；
   - `on_message` / `on_llm_request` / `on_waiting` / 工具注册等钩子不动；
   - 普通模式的缓存键、输出笔记、提示词保持原样。

2. **增强模式默认关闭**
   - 新增 `enhanced_mode: false`；
   - 只有 `true` 时，帧处理与笔记阈值才走增强分支。

3. **增强模式失败必须能回退**
   - 任何一步失败（取流、采样、DP 装箱、拼图）都不能让观看直接失败；
   - 回退到普通模式，并在笔记里记录一条警告。

4. **不改 B站之手**
   - 增强模式只影响 B站之眼的材料与笔记；
   - 下游 `get_last_video()` 返回结构不变。

## 2. 总体架构

```text
                    enhanced_mode = false
用户看视频 ──────────────────────────────→ 现有 _collect / _fill_frames / _digest
                    enhanced_mode = true
                          │
                          ▼
                  _fill_frames_enhanced
                          │
           ┌──────────────┼──────────────┐
           │              │              │
      低分辨率采样     变化选帧       高清抽帧
      (ffmpeg)       (HSV + 切点     (选中时间点)
                       + 积分 + 去重)
                          │
                          ▼
                   tiers 档位计算
                          │
                          ▼
                 完整 DP 拼图装箱
                          │
                          ▼
                 一张增强联系图
                          │
                          ▼
             Material.frames = [sheet]
             Material.frame_layout = 格号/时间/档位
                          │
                          ▼
              _digest: enhanced_digest_max_chars
```

普通模式路径完全不进入新模块。

## 3. 新增文件与职责

建议新增一个独立模块，避免把普通模式代码搅乱：

```text
eyes_enhanced.py
  ├─ EnhancedConfig           # 增强参数
  ├─ FrameSample              # 时间、分数、低分辨率数据
  ├─ select_keyframes()       # 切点 + 积分 + 去重
  ├─ assign_tiers()           # 档位计算
  ├─ solve_layout()           # DP 装箱（完整移植）
  ├─ to_rects()               # 归一化格子 → 像素矩形
  ├─ compose_sheet()          # PIL 拼图 + 格号 + 时间标签
  └─ make_frame_layout()      # 供提示词使用的元数据
```

保持 `eyes_client.py` 只负责「取流 / 抽帧」等 B站数据层操作，不把算法塞进去。

## 4. 配置设计

### 4.1 基础开关

| 配置 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `enhanced_mode` | bool | `false` | 增强模式总开关 |
| `enhanced_frame_count` | int | `24` | 增强模式目标帧数，范围 8~32 |
| `enhanced_sample_fps` | int | `2` | 低分辨率采样帧率，范围 1~4 |
| `enhanced_max_analysis_seconds` | int | `1200` | 最多分析视频前 N 秒，避免超长视频 CPU 爆炸 |
| `enhanced_sheet_size` | int | `1024` | 方形拼图画布边长，可选 768/1024/1280 |
| `enhanced_digest_max_chars` | int | `4000` | 增强模式笔记上限（普通 1500） |
| `enhanced_subagent_timeout` | int | `300` | 增强笔记更长，子代理超时放宽（普通 180） |
| `enhanced_fallback_to_normal` | bool | `true` | 增强流程失败时回退普通模式 |

### 4.2 选帧高级参数

这些可以放在高级配置，默认值先按 SeeNow 的屏幕标定值起步，后续用 B站素材重标：

| 配置 | 默认 | 说明 |
| --- | ---: | --- |
| `enhanced_cut_abs` | 12 | 绝对变化地板 |
| `enhanced_cut_spike` | 2.5 | 尖峰倍数 |
| `enhanced_cut_min_gap` | 0.4 | 两次切点最小间隔（秒） |
| `enhanced_integral_seconds` | 3 | 中等运动积分窗口（秒） |
| `enhanced_dup_min` | 8 | 与上一保留帧的相似度阈值 |
| `enhanced_silent_floor_seconds` | 20 | 长时间无变化时的兜底帧间隔 |

### 4.3 普通模式相关配置保持不动

```text
frame_source
subagent_frame_mode
frame_count
frame_height
digest_max_chars
subagent_timeout
```

增强模式**忽略** `subagent_frame_mode`，固定输出一张增强拼图；普通模式不受影响。

## 5. 增强模式执行流程

### 5.1 一次低分辨率采样

新增一个同步生成器（放在 `eyes_client.py` 或 `eyes_enhanced.py`，由插件线程池调用）：

```python
sample_lowres_frames(
    stream_url,
    output_w=64,
    output_h=36,
    fps=2,
    max_seconds=1200,
    referer="https://www.bilibili.com/",
) -> Iterator[FrameSample]
```

ffmpeg 命令示意：

```text
ffmpeg -headers "Referer: ..." -i <stream>
  -t <max_seconds>
  -vf "fps=2,scale=64:36"
  -f rawvideo -pix_fmt rgb24 -
```

注意：

- 只启动一次 ffmpeg，不要按时间点启动；
- stdout 读 raw RGB24，stderr 单独读取，避免管道卡死；
- 每帧时间按 `索引 / fps` 估算；如果需要更准，解析 ffmpeg `showinfo` 时间戳；
- 只保留分数与时间，不保留低分辨率帧本身；
- 超过时长上限就停止，并标记“只分析了前 N 秒”。

### 5.2 变化分与选帧

在 Python 中实现 SeeNow 的 HSV 加权差：

```text
rgb → HSV
色相按环形距离
低饱和像素的色相降权
三通道绝对差平均 → 0–255
```

离线场景可以使用未来帧，不需要 SeeNow 的因果延迟：

```text
score[i] = 当前帧与上一帧的 HSV 差
cut[i]  = score[i] >= cut_abs
          且 score[i] > cut_spike × max(1, score[i-1], score[i+1])
          且 t[i] - last_cut >= cut_min_gap

integral += score[i]
if integral >= REF_SCORE(4) × fps × integral_seconds:
    取当前帧
    integral = 0
```

再执行：

- 与上一张保留帧的 HSV 差 `< dup_min` 时丢弃（切点帧可豁免）；
- 静止兜底：超过 `silent_floor_seconds` 没有新帧时补一帧；
- 首帧/尾帧保证至少各一个候选；
- 候选超过 `enhanced_frame_count` 时，按“切点优先、覆盖均匀、时间不重复”筛选；
- 候选不足时，用现有 `select_timestamps` / 均匀采样补齐。

**关键原则**：增强选帧是“新增候选源”，不是完全替换现有热点。  
第一版建议采用 `hybrid`：变化候选 + 均匀保底，避免 B站动画/游戏画面把变化分拉爆后漏掉语义段。

### 5.3 高清抽帧

对最终时间点抽取高清帧：

- 第一版直接复用现有 `client.extract_frames()`，保证行为可控；
- 第二版再做“一次 ffmpeg 批量输出选中帧”，减少 24 次进程启动；
- 保持 `frame_height` / `max_frame_mb` 作为高清帧参数；
- 每帧记录实际时间戳，后续标签用实际时间。

### 5.4 档位计算

完整移植 SeeNow 的 `tiers` 思路，但离线输入不是连续 fps，而是入选帧时间序列。

建议：

1. 以 `enhanced_density_window_seconds`（默认 2 秒）为窗口；
2. 统计每个入选帧所在窗口内的帧密度 `F`（帧/秒）；
3. 按 SeeNow 的档位映射：

```text
k ≈ clamp(ceil(sqrt(T × F)), 1, 8)
```

其中 `T` 为窗口覆盖的目标时长（默认 16 秒）；
4. 保留滞回逻辑，避免相邻帧档位来回跳；
5. 也可以直接移植 `tiers.js` 的 7 道阈值，但需要把“实时 tick”改成“按入选时间排序后逐帧计算”。

第一版建议先实现一个简化版档位：

```text
密度低 → tier 1~2（格子大，看不清细节）
密度中 → tier 3~4
密度高 → tier 5~8（格子小，塞更多帧）
```

然后用真实素材对比完整移植版，决定是否值得引入全部滞回逻辑。

### 5.5 完整 DP 拼图装箱

这是本方案的核心，按 SeeNow 的 `pack.js` 完整移植为 Python：

```text
UNIT = 840
TIER_MIN = 1
TIER_MAX = 8
FREE = 0
bin_cost = 1000        # 强制只开一张图
```

实现内容：

1. `row_options(tiers)`：
   - 一行内不同档位格子的候选边长；
   - 行高、面积、拉伸；
   - 最小档候选，避免“2+1”排法被误判装不下；
2. `solve(tiers)`：
   - 按行 DP，寻找占用率最高的排布；
   - `bin_cost=1000` 让算法优先把帧塞进同一张图；
3. `to_rects()`：
   - 把归一化方形容器中的格子转成像素矩形；
4. `split_one_bin()`：
   - 兜底：一箱装不下时拆分/降级；
5. 单张画布：
   - 默认 `1024×1024` 方形；
   - 每个格子放 16:9 帧，采用“等比缩放 + 上下留黑边”，不拉伸画面；
   - 烧格号 + 时间标签；
   - 背景深灰，缝隙 4~8px；
   - 保存为 JPEG/PNG（JPEG 质量 90 优先，减少 token）。

**为什么不直接把 16:9 视频塞进方形 DP：**

SeeNow 的 DP 以方形格子为基础。B站视频是 16:9，如果直接按方形拉伸会变形；  
所以统一用“方形格子 + 格子内 16:9 等比缩放 + letterbox”，既保留 DP 算法，又不破坏画面。

### 5.6 输出 Material 结构

增强模式使用一张 sheet 作为视觉材料，但要保留格号映射：

```python
material.frames = [sheet_path]
material.frame_times = [-1.0]
material.frame_layout = [
    {"index": 1, "time": 12.3, "tier": 2, "rect": [x, y, w, h]},
    ...
]
material.enhanced_sheet = True
```

普通模式这些字段为空，行为不变。

### 5.7 提示词接入

只改 `build_material_prompt()` 的增强分支，不改普通分支：

```text
这是一张增强拼图，按格号顺序对应时间点：
1  00:12  tier=2
2  00:19  tier=3
...
格号越小越靠前；时间戳是抽帧时间，不是精确字幕时间。
```

然后继续追加原有的字幕/评论/弹幕/简介。

要避免模型把拼图当成单张截图：

- 明确告诉它这是多帧拼图；
- 给出格号与时间映射；
- 说明“不要把不同格子的内容当成同一时刻”。

## 6. 普通模式保持不变的具体做法

### 6.1 `_fill_frames` 拆成两个实现

当前 `_fill_frames` 内含普通模式全部逻辑。建议：

```python
async def _fill_frames(self, material, event):
    if self._bool_opt("enhanced_mode"):
        ok = await self._fill_frames_enhanced(material, event)
        if ok:
            return
        if not self._bool_opt("enhanced_fallback_to_normal"):
            return
        material.warnings.append("增强取帧失败，已回退普通模式")
    await self._fill_frames_normal(material, event)
```

- `_fill_frames_normal` = 原函数内容原样搬过去；
- `_fill_frames_enhanced` = 新流程；
- 普通模式的 `frame_source`、`subagent_frame_mode`、联系图逻辑一行不改。

### 6.2 `_digest` 只改阈值选择

```python
max_chars = (
    enhanced_digest_max_chars
    if enhanced_mode
    else digest_max_chars
)
timeout = (
    enhanced_subagent_timeout
    if enhanced_mode
    else subagent_timeout
)
```

其余 `run_digest` 调用、缓存、提示词逻辑不变。

### 6.3 钩子完全不动

以下全部保持原样：

- `on_message`
- `on_llm_request`
- `on_waiting`
- 自然语言触发
- `/看视频`、`/看主页`、`/bili状态`
- `bilibili_watch`、`bilibili_ask`、`bilibili_frame`
- 权限、配额、冷却、等待提示、单飞锁

增强模式只在 `_fill_frames` 和 `_digest` 两个内部函数里分支。

## 7. 笔记阈值放宽

### 7.1 主阈值

| 项目 | 普通模式 | 增强模式 |
| --- | ---: | ---: |
| 笔记字符上限 | 1500 | **4000** |
| 子代理超时 | 180s | **300s** |
| 目标帧数 | 12 | **24** |
| 笔记输出结构 | 现有六段式 | 沿用，但允许更长时间轴/更多细节 |

### 7.2 为什么只放宽输出阈值

增强模式的输入材料更多（24 帧 + 拼图布局），如果仍按 1500 字截断，会丢掉：

- 更多时间轴细节；
- 更多「观众观点」；
- 更多「不确定项」。

因此：

- `enhanced_digest_max_chars=4000`；
- `enhanced_subagent_timeout=300`；
- 仍保留 `truncate_digest()` 的“优先保留观众观点/不确定项”策略，不改变截断算法；
- 不建议无限放宽，避免主模型上下文被笔记挤满。

### 7.3 缓存隔离

普通与增强的笔记不能混用：

- `NoteCache` 增加 `variant` 参数：
  - 普通模式：`variant=""`，路径保持原样；
  - 增强模式：`variant="enhanced"`，路径追加 `_enhanced`；
- `_video_key` 在增强模式下追加 `|enhanced`；
- `NoteCache` 版本号不需要整体升级，避免普通缓存全部失效。

## 8. 失败与回退策略

按顺序回退：

```text
增强选帧失败
  → 高清抽帧失败
  → DP 装箱失败
  → 拼图失败
  → 回退普通 _fill_frames
  → 仍失败则沿用现有“无视觉、文本笔记”降级
```

所有失败只记录语义 warning：

```text
增强取帧失败，已回退普通模式
增强拼图失败，已回退普通模式
```

不把 ffmpeg/PIL 的原始异常直接塞进笔记。

## 9. 测试计划

### 9.1 纯函数测试

新增 `tests/test_enhanced.py`：

- HSV 变化分：
  - 相同帧 → 0；
  - 完全换色 → 高分；
  - 亮度变化/低饱和 → 合理权重；
- 切点：
  - 孤立尖峰保留；
  - 持续运动不因尖峰被切碎；
  - 不应期生效；
- 积分：
  - 持续中等变化累计后出帧；
  - 静止不出帧；
- 去重：
  - 连续相似帧只留一张；
- 档位：
  - 帧密 → tier 高；
  - 帧稀 → tier 低；
- DP：
  - 所有帧都有位置；
  - 无重叠、无越界；
  - 单箱优先；
  - 与手算布局一致；
- 拼图：
  - 输出尺寸正确；
  - 标签数量等于帧数；
  - 16:9 帧不变形（黑边存在）。

### 9.2 集成测试

- `enhanced_mode=false`：现有测试全部通过，输出不变；
- `enhanced_mode=true` + 假流 + 假帧：走增强分支，生成 sheet；
- 增强分支异常：回退普通路径；
- `enhanced_digest_max_chars`：超过 1500 的笔记不被截到 1500；
- 缓存隔离：普通与增强各自命中，不串；
- 单飞锁：同一视频普通/增强并发不互相复用结果。

### 9.3 真机 A/B

选 10~20 个视频，覆盖：

- 教程/幻灯片；
- 动画；
- 影视剪辑；
- 游戏实机；
- 静态 PPT；
- 长视频（>30 分钟）。

对比：

- 重复帧比例；
- 关键画面召回；
- 笔记长度/信息量；
- 总耗时；
- token 成本。

## 11. 风险与待定项

| 风险 | 说明 | 对策 |
| --- | --- | --- |
| B站画面变化噪声 | 动画、游戏、转场会拉高分数 | 先 hybrid，保留普通候补，调阈值 |
| DP 移植复杂 | JS → Python 的边界/浮点差异 | 纯函数单测 + 手算 fixtures |
| 方形画布 + 16:9 | 上下黑边浪费画布 | 先接受；后续可做矩形 DP |
| 24 帧高清抽帧慢 | 每帧一次 ffmpeg | 第一版复用；第二版批量 |
| 长视频 CPU | 2fps 全片采样 | `enhanced_max_analysis_seconds` 上限 |
| 缓存串用 | 普通/增强笔记不同 | cache variant + video key |
| 笔记过长 | 4000 字挤压主模型上下文 | 保持截断策略，按需调 |

**待你确认的设计选择：**

1. 增强模式的开关名用 `enhanced_mode`，还是更明确的 `processing_mode: normal/enhanced`？
2. 拼图画布用方形 `1024×1024` + 16:9 letterbox，还是做 16:9 矩形 DP（实现更复杂）？
3. 增强模式默认帧数 `24` 是否合适，还是先 `16` 降低成本？
4. 笔记上限 `4000` 字是否够，还是要 `5000/6000`？

## 13. 结论

这个增强模式可以做到**完全旁路**：

```text
enhanced_mode=false → 原代码路径，一行行为不变
enhanced_mode=true  → 新模块：变化选帧 + 档位 + 完整 DP 拼图 + 更宽笔记阈值
```

最值得先做的是：

1. 把普通 `_fill_frames` 原样抽成 `_fill_frames_normal`；
2. 用纯 Python 实现选帧与 DP；
3. 增强模式默认关闭、失败回退普通模式；
4. 先用“普通联系图 + 增强选帧”验证质量，再接完整 DP 拼图。

这样风险最低，也符合“现有模式与钩子不动”的要求。
