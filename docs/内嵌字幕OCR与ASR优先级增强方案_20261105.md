## 1. 背景

当前文本证据来源只有两类：

1. B 站官方字幕（含人工字幕和 B 站 AI 字幕）；
2. 本地 ASR 音频转录。

这会导致两个问题：

### 1.1 内嵌字幕没有被利用

有些视频没有 B 站字幕轨，但画面里已经烧录了字幕。当前流程会忽略这些文字，直接进入 ASR，或者在没有 ASR 时完全失去文本证据。

### 1.2 ASR 幻觉优先级过高

ASR 是对音频的二次推断，遇到无语音、音乐、环境声、多人声、口音时容易：

- 重复无意义短语；
- 出现大量 `why?`、`what?` 之类的空句；
- 把背景音乐识别成台词；
- 语言与视频内容不符；
- 产生看似连贯但实际不存在的内容。

如果视频本身有内嵌字幕，却优先使用 ASR，会明显降低笔记质量。

## 2. 修正后的优先级

### 2.1 默认优先级

```text
1. 官方人工字幕
2. B站 AI 字幕
3. 内嵌画面字幕 OCR
4. 本地 ASR
```

**硬规则：ASR 永远是最后兜底，不能覆盖人工字幕、AI 字幕或内嵌 OCR。**

### 2.2 可选严格视觉模式

对特别强调画面原文的视频，可配置为：

```text
1. 官方人工字幕
2. 内嵌画面字幕 OCR
3. B站 AI 字幕
4. 本地 ASR
```

即：

```text
ocr_subtitle_priority = after_ai  # 默认
ocr_subtitle_priority = before_ai # 严格视觉模式
```

### 2.3 来源定义

| 来源 | 标识 | 可信度 | 说明 |
| --- | --- | --- | --- |
| 官方人工字幕 | `official` | 最高 | 平台提供的人工翻译/字幕 |
| B站 AI 字幕 | `ai` | 较高 | `lan` 以 `ai-` 开头或 `ai_type` 非空 |
| 内嵌 OCR | `ocr` | 中 | 画面实际文字，可能有 OCR 错字 |
| 本地 ASR | `asr` | 最低 | 仅在前三者不可用时使用 |

## 4. 总体流程

```text
取播放器字幕轨
  │
  ├─ 有人工字幕
  │    → 使用人工主/辅字幕
  │
  ├─ 只有 B站 AI 字幕
  │    → 按 ocr_subtitle_priority：
  │         after_ai  → AI 为主
  │         before_ai → OCR 为主，AI 为辅
  │
  └─ 无官方字幕
       → 如果 OCR 启用：
            抽取内嵌字幕
            成功且覆盖足够 → 使用 OCR
            失败/覆盖不足 → 尝试 ASR
       → 如果 OCR 未启用：
            尝试 ASR
```

### 4.1 伪代码

```python
human = [t for t in official_tracks if not t.is_ai]
ai = [t for t in official_tracks if t.is_ai]

if human:
    tracks = human
elif ai and ocr_priority == "after_ai":
    tracks = ai
elif ocr_enabled:
    ocr_tracks = extract_embedded_subtitles(...)
    if ocr_tracks and coverage_ok:
        tracks = ocr_tracks
    else:
        tracks = ai or []
else:
    tracks = ai

if not tracks and asr_enabled:
    asr_tracks = transcribe_audio(...)
    if asr_quality_ok(asr_tracks):
        tracks = asr_tracks
```

注意：`audio_transcription_mode=always` 仍然可以在有 OCR 时补充 ASR，但 **不能覆盖 OCR**，只能作为“低可信补充材料”。

## 5. 内嵌 OCR 方案

### 5.1 新增模块

建议新增：

```text
eyes_ocr.py
```

职责：

- 从视频流按时间采样；
- 裁剪字幕区域；
- 调用 OCR；
- 过滤、去重、合并时间轴；
- 输出 `SubtitleTrack`。

不把 OCR 逻辑塞进 `eyes_client.py`，避免数据层继续膨胀。

### 5.2 采样

默认：

```text
1 fps
```

可配置：

```text
ocr_subtitle_fps = 1
```

快速字幕视频可提高到 2 fps。

### 5.3 画面区域

默认底部区域：

```text
crop=width:height*0.32:0:height*0.68
```

即只保留画面底部约 32%。

可选：

```text
ocr_subtitle_region = auto / bottom / top
```

`auto` 模式：

1. 每 30 秒抽一帧整帧做文字检测；
2. 统计文字框位置；
3. 如果文字主要不在底部，自动调整 ROI；
4. 避免顶部注释、标题、歌词被误判为字幕。

### 5.4 跳过重复帧

不要对每一帧都 OCR。

- 计算相邻采样帧 ROI 的差异；
- 差异小于阈值时跳过 OCR；
- 字幕变化时才识别；
- 同一句字幕通常连续 2~5 秒，1 fps 足够。

### 5.5 OCR 后端

按推荐顺序：

1. **RapidOCR / ONNX Runtime**
   - 轻量，CPU 可跑；
   - 适合作为默认后端；
   - 作为可选依赖，不塞进基础 `requirements.txt`。

2. **PaddleOCR**
   - 中文、复杂排版更稳；
   - 依赖和模型体积较大；
   - 作为高精度可选后端。

3. **视觉模型 OCR**
   - 适合花字、艺术字、双语排版；
   - token 成本和延迟高；
   - 只作为低置信度帧的兜底，不做全量。

Tesseract 对中文硬字幕稳定性一般，不作为首选。

### 5.6 去重与时间轴

OCR 原始结果：

```text
[12.0s] 这就是问题所在
[13.0s] 这就是问题所在
[14.0s] That's exactly the problem
[15.0s] That's exactly the problem
```

处理规则：

- 文本相似度 > 0.85 视为同一条；
- 合并连续帧，取置信度最高的识别结果；
- 时间范围为 `[start, end]`；
- 持续时间 < 0.3 秒的结果丢弃；
- 纯符号、台标、水印、片头片尾文字丢弃。

输出：

```text
[(12.0, "这就是问题所在"), (14.0, "That's exactly the problem")]
```

### 5.7 双语内嵌字幕

如果字幕区域稳定出现上下两行：

```text
这就是问题所在
That's exactly the problem
```

处理：

- OCR 按行切分；
- 按字符集判断中文/英文；
- 上下两行稳定配对时生成两条 OCR 轨：
  - `role=primary`
  - `role=secondary`
- 只有一条混合行时保留原样，标记 `bilingual=true`。

### 5.8 OCR 置信度

`SubtitleTrack` 增加：

```python
origin: str = "official"  # official / ai / ocr / asr
confidence: float = 1.0
```

OCR 默认阈值：

```text
ocr_subtitle_min_confidence = 0.6
```

低于阈值的行：

- 不进入主文本；
- 可写入“不确定项”；
- 不能用来编造剧情。

## 6. ASR 最后兜底与质量检查

### 6.1 触发条件

ASR 只在以下情况运行：

```text
没有人工资格字幕
且没有 B站 AI 字幕（或 AI 被配置为让位给 OCR）
且 OCR 未启用 / OCR 失败 / OCR 覆盖不足
或用户显式设置 audio_transcription_mode=always
```

推荐新增语义：

```text
audio_transcription_mode:
  fallback  = 官方/AI/OCR 都不可用时才 ASR
  always    = 仍运行 ASR 作为补充，但不覆盖更高优先级文本
```

`no_subtitle` 保留为兼容别名，内部按 `fallback` 处理。

### 6.2 质量检查

ASR 结果进入笔记前检查：

- 重复短语比例；
- 连续相同句比例；
- 平均句长；
- 问句/语气词比例；
- 语言与标题/简介是否明显不符；
- 与 OCR 文本的冲突程度；
- 是否出现大量无意义 `why?`、`what?` 等。

例如：

```text
why? why? why? why?
```

应判定为低质量 ASR，不进入笔记正文。

### 6.3 状态

建议增加：

```text
asr_status = available / absent / failed / low_quality / skipped
```

低质量时不覆盖 OCR，只在诊断和“不确定项”中记录。

## 7. 提示词规则

文本来源标签：

```text
官方人工字幕：
官方 AI 字幕：
内嵌字幕 OCR（可能有错字，时间戳近似）：
ASR（低可信，可能在无语音段产生幻觉）：
```

子代理规则：

1. 人工字幕优先；
2. AI 字幕次之；
3. OCR 与 ASR 冲突时，以 OCR 为准；
4. ASR 只作为最后叙述线索；
5. ASR 中重复、空句、无意义问句不能写进核心内容；
6. 所有看不清、低置信度的句子写入“不确定项”。

## 8. 原文缓存与检索

`TranscriptStore` 的每轨增加：

```json
{
  "origin": "ocr",
  "is_ai": false,
  "confidence": 0.82,
  "lines": [[12.0, "这就是问题所在"]]
}
```

兼容旧缓存：

- 旧 `tracks` 没有 `origin` → 默认 `official`；
- 旧 JSON 没有 `tracks` → 按原 `official` 合成；
- 不批量迁移旧文件。

`bilibili_transcript`：

```text
source = official / ai / ocr / asr / both
```

输出标签：

```text
[00:12] 内嵌 OCR：这就是问题所在
[00:14] ASR（低可信）：...
```

`lang` 过滤继续支持。

## 9. 极致模式

`estimate_text_profile()` 改为按优先级取文本：

```python
if human:
    lines = human
elif ai and priority == after_ai:
    lines = ai
elif ocr:
    lines = ocr
elif asr_quality_ok:
    lines = asr
else:
    lines = []
```

效果：

- 有内嵌字幕时，文本画像不全为 0；
- 场景分配能利用 OCR 文本；
- 低质量 ASR 不抬高文本分数；
- 无文本视频仍走全时段均匀兜底。

## 10. 配置项

新增：

```text
ocr_subtitle_enabled = true
ocr_subtitle_mode = auto
ocr_subtitle_fps = 1
ocr_subtitle_min_confidence = 0.6
ocr_subtitle_region = auto
ocr_subtitle_priority = after_ai
ocr_engine = rapidocr
```

语义：

- `ocr_subtitle_enabled`：总开关；
- `ocr_subtitle_mode`：`auto/fallback/always`；
- `ocr_subtitle_fps`：采样频率；
- `ocr_subtitle_min_confidence`：OCR 置信度阈值；
- `ocr_subtitle_region`：`auto/bottom/top`；
- `ocr_subtitle_priority`：`after_ai/before_ai`；
- `ocr_engine`：`rapidocr/paddleocr/vlm`。

现有 ASR 配置改为：

```text
audio_transcription_mode = fallback / always
```

`no_subtitle` 继续兼容，但实际按 `fallback` 处理。

## 11. 缓存与失效

笔记 meta 增加：

```json
{
  "text_origin": "ocr",
  "text_sources": ["ocr"],
  "ocr_checked": true,
  "asr_status": "skipped"
}
```

规则：

- 旧笔记没有 `ocr_checked` 时，启用 OCR 后忽略一次旧缓存；
- OCR 配置变化（开关/优先级/引擎）建议失效笔记缓存；
- 原文缓存按 `origin` 保存，不覆盖官方轨。

## 12. WebUI

视频详情：

```text
字幕来源：
  官方人工字幕：中文
  B站 AI 字幕：无
  内嵌 OCR：中文 + English
  ASR：低质量，未采用
```

原文检索：

- 来源下拉增加 `内嵌 OCR`；
- 结果标签显示来源和置信度；
- 低质量 ASR 用灰色/警示标记。

诊断页：

- OCR 是否启用；
- 最近 OCR 耗时；
- ASR 质量状态；
- 文本来源优先级。

## 13. 测试计划

### 单元测试

1. 人工字幕存在时，不触发 OCR/ASR；
2. 只有 AI 字幕时，默认选 AI；
3. `before_ai` 时 OCR 优先于 AI；
4. 无官方字幕时，OCR 优先于 ASR；
5. OCR 覆盖不足时，ASR 才运行；
6. ASR 出现大量重复 `why?` 时判定 `low_quality`；
7. OCR 连续帧去重；
8. 双语 OCR 行拆成两条轨；
9. `TranscriptStore` 旧格式兼容；
10. `bilibili_transcript` 支持 `source=ocr` 和 `lang`；
11. 极致文本画像使用 OCR，不使用低质量 ASR。

### 真实视频测试

- 无字幕无音频视频；
- 有内嵌中英字幕的视频；
- 有官方字幕的视频；
- ASR 幻觉明显的视频；
- 3 分钟 / 10 分钟长视频。

### 验收标准

```text
有官方人工字幕：不跑 OCR/ASR
有 AI 字幕：按配置选择 AI 或 OCR
无官方/AI、有内嵌字幕：使用 OCR，ASR 不参与主文本
OCR 失败：才回退 ASR
ASR 幻觉：不进入核心笔记
```

## 14. 实施顺序

1. `eyes_ocr.py`：ROI 裁剪、采样、OCR、去重、双轨输出；
2. `SubtitleTrack` / `Material` 增加 `origin`、`confidence`；
3. 重排 `_fetch_video_material()`：官方 → OCR → ASR；
4. ASR 质量门；
5. `TranscriptStore` 保存/检索 OCR 轨；
6. 提示词与极致文本画像；
7. WebUI 展示；
8. 测试与真实视频验收；
9. 版本号按发布节奏另行决定（本方案不绑定 0.13.0）。

## 15. 风险与限制

- OCR 依赖额外库和模型，首次安装体积较大；
- 1 fps 可能漏掉极短字幕；
- 花字、艺术字、竖排字幕识别率有限；
- 字幕不一定固定在底部，需要 `auto` ROI；
- OCR 错字可能改变专有名词，必须标注低置信度；
- ASR 质量门只能降低幻觉，不能完全消除；
- OCR 处理会增加无字幕视频的耗时，默认 fallback 控制成本；
- 不把 OCR 结果说成“官方字幕”。

## 16. 不在本方案范围

- 实时视频/直播字幕；
- 弹幕文字 OCR；
- 视频画面翻译；
- 训练专用 OCR 模型；
- 自动生成双语翻译（OCR 只识别已有文字）。
