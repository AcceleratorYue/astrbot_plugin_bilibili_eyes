# 下一轮规划：P1（Phase 2 收尾）

> 基线：v0.2.7（P0 已完成）
> 目标：完成追问/附图，让「看视频」从一次性笔记变成可追问的会话材料。

## 1. 本轮目标

- `bilibili_frame(bvid, 时间点)`：按需返回单帧图。
- `bilibili_ask(bvid, 问题)`：基于会话缓存材料回答追问。
- 原始材料会话保留 30 分钟（F12），作为上面两个工具的基础。
- 联系图（`subagent_frame_mode=contact_sheet_plus`）作为可选项。

## 2. 任务拆分与顺序

### P1-1 材料会话缓存（F12）

**做什么**

- 新增 `MaterialCache`：按 `umo` 保存 `Material`（帧路径、时间点、字幕、评论、视频信息）与创建时间；
- TTL 30 分钟；访问时清理过期项；限制单会话材料大小；
- 只保留在内存，不写长期存储。

**验收**

- 看完视频后 30 分钟内可复用材料；
- 过期后 `bilibili_ask`/`bilibili_frame` 明确提示「已过期，请重新看一次」；
- 不影响现有笔记缓存（F11）。

### P1-2 `bilibili_frame` 工具

**做什么**

- 参数：`bvid`/`时间点`（秒或 `mm:ss`）/可选 `page`；
- 从缓存取对应帧；没有则用 ffmpeg 单帧截取（限制并发/超时）；
- 返回 `CallToolResult(content=[TextContent, ImageContent])`，路径必须在插件数据目录内；
- 只允许显式「截图/这一帧」类请求调用。

**验收**

- 主模型调用后能收到图片；
- 非法时间点/路径被拒绝；
- 不重复抓取已有帧。

### P1-3 `bilibili_ask` 工具

**做什么**

- 参数：`bvid`/`问题`；
- 基于会话材料（字幕/评论/笔记/帧）用子代理回答，返回短答案；
- 不重新抓 B 站；材料过期或缺失时提示重新看；
- 答案仍受 `digest_max_chars` 约束。

**验收**

- 看完视频后能追问「第 30 秒发生了什么」「评论在吵什么」；
- 不产生新的 B 站请求（日志可验证）；
- 不会把整份材料塞给主模型。

### P1-4 联系图可选模式

**做什么**

- `subagent_frame_mode=contact_sheet_plus`：12 帧合成 1 张联系图 + 4 张关键原图；
- 作为省 token/提速选项，默认仍 individual。

**验收**

- 同一视频两种模式都能出笔记；
- 联系图模式的 prompt token 明显下降；
- 截图质量可接受。

### P1-5 测试与文档

- Mock `llm_generate` 测试 `ask`；测试 frame 时间点解析、路径校验、TTL 过期；
- 更新 README 配置/工具说明、CHANGELOG、SPEC、PROGRESS；
- 版本发布 v0.3.0。

## 3. 本轮不做

- 番剧/直播/动态；
- 音频转录（继续留桩）；
- 长期记忆；
- 插件市场发布（放 P2/Phase 4）。

## 4. 风险

- AstrBot 4.29 的 `ImageContent` 工具返回需要先做最小烟测，确认主模型能收到图片；
- 材料缓存的帧文件占磁盘，需要 TTL 清理；
- `bilibili_ask` 仍走 LLM，需限制并发，避免和其它会话抢 provider。

## 5. 完成定义（Definition of Done）

- 三个新能力在真实机器人上各跑通一次；
- 离线测试全绿，新增 mock 测试；
- 文档与版本号同步，打 tag `v0.3.0`；
- PROGRESS.md 记录本轮完成项与遗留项。
